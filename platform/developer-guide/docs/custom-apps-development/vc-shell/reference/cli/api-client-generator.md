# API Client Generator

The CLI that generates typed TypeScript clients from a Virto Commerce Platform's OpenAPI documents. The generator shells out to NSwag for the actual code emission and the framework's `authApiBase.ts` template, then writes per-module `<module>.ts` files into a single output directory.

The CLI is published as **@vc-shell/api-client-generator**. Apps generated by `create-vc-app` already declare it as a dev dependency and expose a `generate-api-client` script in **package.json**.

## Synopsis

```bash
yarn generate-api-client [options]
# or, without a project script:
npx @vc-shell/api-client-generator [options]
```

## Two modes

The generator runs in one of two modes depending on what it finds at `APP_API_CLIENT_DIRECTORY`:

| Mode | Trigger | What it does |
| --- | --- | --- |
| **Simple** (default). | No **package.json** in the output directory and no `--PACKAGE=true`. | Generates `<module>.ts` files and `authApiBase.ts` next to them. Nothing else. |
| **Package**. | **package.json** exists in the output directory **or** `--PACKAGE=true` is passed. | After generation, writes a **tsconfig.json**, runs `tsc`, and writes a **package.json** with proper exports. The output directory becomes a standalone npm package. |

`SKIP_BUILD=true` forces simple-mode behavior even when package mode would otherwise activate; the **package.json** and **tsconfig.json** are not touched and `tsc` is skipped.

## Configuration sources

The generator reads options from three places. When the same option is set in more than one, the order of precedence is:

1. Shell environment variable.
2. Command-line argument.
3. (For `APP_TYPE_STYLE` only) auto-detection from existing files in the target directory.

The project's **.env** file is loaded by the runner (Vite-style `dotenv`) into the shell environment, so values in **.env** behave like environment variables.

## Core options

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `APP_PLATFORM_URL`. | string. | Required. | Platform URL used to discover module OpenAPI documents. A trailing slash is added automatically if missing. |
| `APP_PLATFORM_MODULES`. | string. | Required. | Comma-separated module list wrapped in brackets, for example `[VirtoCommerce.Catalog, VirtoCommerce.Orders]`. Whitespace inside brackets is allowed. |
| `APP_API_CLIENT_DIRECTORY`. | string. | Required. | Output directory for generated `.ts` files. Resolved relative to the current working directory. Created if it does not exist. |
| `APP_TYPE_STYLE`. | string. | Auto-detected. | DTO type style. Exactly `Class` or `Interface`, case-sensitive. See [Auto-detection of type style](#auto-detection-of-type-style). |
| `RUNTIME`. | string. | `Net80`. | .NET runtime version used by NSwag. Known values: `Net80`, `Net90`, `Net100`. An unknown value prints a warning and is passed through; NSwag itself errors if the runtime is unsupported. |
| `VERBOSE`. | boolean. | `false`. | Enable detailed generator and NSwag output. Pass `--VERBOSE=true`. |

## Package-mode options

These apply only when the generator is in package mode (see [Two modes](#two-modes)):

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `APP_PACKAGE_NAME`. | string. | `api-client`. | Package name written into the generated **package.json**. |
| `APP_PACKAGE_VERSION`. | string. | `1.0.0`. | Package version written into the generated **package.json**. |
| `APP_OUT_DIR`. | string. | `./`. | Output directory used for declaration files (`<outDir>/types`). Not the compile output — that is controlled by `APP_BUILD_DIR`. |
| `APP_BUILD_DIR`. | string. | `dist`. | Directory where `tsc` compiles the generated TypeScript files. Becomes the `outDir` in **tsconfig.json**. |
| `SKIP_BUILD`. | boolean. | `false`. | Skip the `tsc` compile step and the **package.json** generation. Useful when iterating on `.ts` files only. |
| `--PACKAGE`. | boolean. | `false`. | CLI argument that forces package mode on. Equivalent to setting the `APP_PACKAGE_MODE=true` environment variable. The variable name `APP_PACKAGE_MODE` is asymmetric with other `APP_*` variables — be aware. |

## Output layout

The generator writes a **flat directory** of `<module>.ts` files. Each input module name is lowercased to form the file name, so `VirtoCommerce.Catalog` becomes `virtocommerce.catalog.ts`. Subdirectories per module are not created.

### Simple mode

```text
src/api_client/
├─ authApiBase.ts                    Generated base class with bearer-token plumbing.
├─ virtocommerce.catalog.ts          One file per module from APP_PLATFORM_MODULES.
├─ virtocommerce.orders.ts
└─ ...
```

Each generated module file exports the Platform client class plus its request, response, and search-query types. The class extends `AuthApiBase` from the sibling `authApiBase.ts`, so the `Authorization: Bearer ${authToken}` header plumbing is shared.

### Package mode

```text
src/api_client/
├─ authApiBase.ts
├─ virtocommerce.catalog.ts
├─ virtocommerce.orders.ts
├─ package.json                      Generated, with exports map and metadata.
├─ tsconfig.json                     Generated, with files[] listing every <module>.ts.
└─ dist/                             APP_BUILD_DIR
   ├─ virtocommerce.catalog.js
   ├─ virtocommerce.orders.js
   └─ types/
      ├─ virtocommerce.catalog.d.ts
      └─ virtocommerce.orders.d.ts
```

### Package-mode exports map

The generator builds the exports map from the module file names. For each module, two keys are emitted: the bare core name and the prefixed full name. Module `VirtoCommerce.Catalog` produces:

```json
{
  "exports": {
    "./catalog":               { "import": "./dist/virtocommerce.catalog.js", "types": "./dist/types/virtocommerce.catalog.d.ts" },
    "./virtocommerce.catalog": { "import": "./dist/virtocommerce.catalog.js", "types": "./dist/types/virtocommerce.catalog.d.ts" }
  }
}
```

When the package contains **a single module**, the generator also writes a root `"."` export and the top-level `module`/`types` fields:

```json
{
  "module": "./dist/virtocommerce.catalog.js",
  "types":  "./dist/types/virtocommerce.catalog.d.ts",
  "exports": {
    ".":                       { "import": "./dist/virtocommerce.catalog.js", "types": "./dist/types/virtocommerce.catalog.d.ts" },
    "./catalog":               { "import": "./dist/virtocommerce.catalog.js", "types": "./dist/types/virtocommerce.catalog.d.ts" },
    "./virtocommerce.catalog": { "import": "./dist/virtocommerce.catalog.js", "types": "./dist/types/virtocommerce.catalog.d.ts" }
  }
}
```

With multiple modules, the root export is omitted unless an existing **package.json** already had one pointing to one of the regenerated modules. In that case, the generator preserves and re-evaluates that root export.

## Auto-detection of type style

When `APP_TYPE_STYLE` is not set explicitly, the generator looks at existing `.ts` files in `APP_API_CLIENT_DIRECTORY` (excluding `index.ts`) and searches for the NSwag class-style pattern `export class <Name> implements I<Name>`. The result:

- Match found in any file. The generator uses `Class` to stay consistent with the existing output.
- No `.ts` files, or no match. The generator uses `Interface`.

The chosen value is logged with its source (`explicit`, `auto-detected`, or `default`) when `VERBOSE=true`. Pass `APP_TYPE_STYLE=Class` or `APP_TYPE_STYLE=Interface` to override the detection.

## Smart merging in package mode

When package mode is active and a **package.json** already exists in the output directory, the generator preserves these user-defined fields across runs:

`name`, `version`, `description`, `keywords`, `author`, `license`, `private`, `scripts`, `devDependencies`, `dependencies`.

The `apiClientGenerator` metadata block is always refreshed:

```json
{
  "apiClientGenerator": {
    "version": "1.1.0",
    "generatedAt": "2026-05-19T12:30:45.123Z"
  }
}
```

For existing exports keys that are not standard keys for the current regeneration, the generator keeps them. Standard keys for regenerated modules are replaced with the canonical shape.

For **tsconfig.json**, the generator preserves `compilerOptions` overrides but always rewrites `outDir` to match `APP_BUILD_DIR` and `declarationDir` to `<APP_BUILD_DIR>/types`. The `files` array is merged with any existing entries.

## Prerequisites

- .NET runtime matching the `RUNTIME` option. Default `Net80`.
- Node.js 22 or higher.
- Network access to `APP_PLATFORM_URL` from the machine that runs the generator.
- For package mode: a working `tsc` binary on the PATH (the generator invokes `npx tsc --project <tsconfig>`).

## Examples

```bash title="Default mode through the project script"
yarn generate-api-client
```

```bash title="Override platform URL at runtime"
APP_PLATFORM_URL=https://admin.example.com yarn generate-api-client
```

```bash title="Direct CLI invocation, no project script"
npx @vc-shell/api-client-generator \
  --APP_PLATFORM_URL=https://admin.example.com \
  --APP_PLATFORM_MODULES='[VirtoCommerce.Catalog, VirtoCommerce.Orders]' \
  --APP_API_CLIENT_DIRECTORY=./src/api_client/ \
  --APP_TYPE_STYLE=Interface
```

```bash title="Force package mode and use a specific .NET runtime"
npx @vc-shell/api-client-generator \
  --PACKAGE=true \
  --APP_PACKAGE_NAME=@my-app/api \
  --APP_PACKAGE_VERSION=1.0.0 \
  --RUNTIME=Net90 \
  --APP_PLATFORM_URL=https://admin.example.com \
  --APP_PLATFORM_MODULES='[VirtoCommerce.Catalog]' \
  --APP_API_CLIENT_DIRECTORY=./packages/api/
```

```bash title="Generate .ts files only, skip package build"
SKIP_BUILD=true yarn generate-api-client
```

```bash title="Verbose run for debugging"
yarn generate-api-client --VERBOSE=true
```

## Troubleshooting

| Symptom | Check |
| --- | --- |
| `APP_PLATFORM_URL is required`. | Set the variable in **.env**, in the shell, or as a CLI argument. |
| `APP_PLATFORM_MODULES is required`. | Set the variable. The value must include brackets, for example `[VirtoCommerce.Catalog]`. |
| `APP_API_CLIENT_DIRECTORY is required`. | Set the variable to a writable path. |
| No client generated for a module. | Confirm the exact Platform module name in `APP_PLATFORM_MODULES`. Names are case-sensitive on the Platform side. |
| NSwag cannot reach the API document. | Open the Platform URL in a browser and verify the module is installed and running. |
| `APP_TYPE_STYLE` error. | Use exactly `Class` or `Interface`. The value is case-sensitive. |
| `Error converting value "$(APP_TYPE_STYLE)" to type ...`. | NSwag received the literal placeholder string instead of an expanded value. Pass `APP_TYPE_STYLE` explicitly through the CLI or shell environment, not as a `$(VAR)` interpolation in a script. |
| `Unknown RUNTIME value`. | Use `Net80`, `Net90`, or `Net100`. The generator only warns; NSwag fails if the chosen runtime is not installed. |
| `tsc` errors after regeneration. | The backend contract changed. Update the module composable or view-model mapping that consumed the previous shape, then rerun `tsc`. |
| Top-level `module`/`types` fields disappeared from **package.json**. | The package now generates more than one module, so root `.` export is suppressed. Consumers should import from `./<module>` subpaths instead. |
