# Authentication Pages

VC-Shell ships pre-built `Login`, `Invite`, `ResetPassword`, and `ChangePasswordPage` components. You wire them as routes; the framework handles the OAuth flow.

These four components are the user-facing surface of the framework's OAuth password-grant flow against the Virto Commerce Platform. The framework owns the protocol (token request, storage, refresh, sign-out, password-policy validation); your app owns the routing, the URLs, and the brand.

All four components are imported from `@vc-shell/framework`, mounted as Vue Router routes, and accept props for `logo`, `background`, and a screen-specific title or token. They render inside `VcAuthLayout`, the centered card layout used across every shared auth screen, and call `useUserManagement` under the hood for `signIn`, `validatePassword`, `resetPasswordByToken`, and `changeUserPassword`.

## Available pages

| Component | Purpose | Typical route |
| --- | --- | --- |
| `Login`. | User sign-in. | `/login`. |
| `Invite`. | Accept an invitation, set initial password. | `/invite`. |
| `ResetPassword`. | Set a new password from a reset-link token. | `/resetpassword`. |
| `ChangePasswordPage`. | Change current password (or forced change after expiry). | `/changepassword`. |

The scaffolder generated by `create-vc-app` wires all four routes for you in **src/router/routes.ts**. The example below mirrors that template.

## Wire the routes

The shared pages are plain Vue components, so they fit any Vue Router configuration. Import them once, then attach each one to a route. The `Invite` and `ResetPassword` pages need to read `userId`, `userName`, and `token` from the URL query string, so use the function form of `props` for those.

```ts title="src/router/routes.ts"
import { RouteRecordRaw } from "vue-router";
import { Login, Invite, ResetPassword, ChangePasswordPage } from "@vc-shell/framework";
import whiteLogoImage from "/assets/logo-white.svg";
import bgImage from "/assets/background.jpg";

export const routes: RouteRecordRaw[] = [
  {
    name: "Login",
    path: "/login",
    component: Login,
    props: () => ({
      logo: whiteLogoImage,
      background: bgImage,
      title: "My Application Portal",
    }),
  },
  {
    name: "Invite",
    path: "/invite",
    component: Invite,
    props: (route) => ({
      userId: route.query.userId,
      userName: route.query.userName,
      token: route.query.token,
      logo: whiteLogoImage,
      background: bgImage,
    }),
  },
  {
    name: "ResetPassword",
    path: "/resetpassword",
    component: ResetPassword,
    props: (route) => ({
      userId: route.query.userId,
      userName: route.query.userName,
      token: route.query.token,
      logo: whiteLogoImage,
      background: bgImage,
    }),
  },
  {
    name: "ChangePassword",
    path: "/changepassword",
    component: ChangePasswordPage,
    props: (route) => ({
      forced: route.query.forced === "true",
      logo: whiteLogoImage,
      background: bgImage,
    }),
  },
];
```

The `Login` page redirects to the `ChangePassword` route automatically when the API response indicates `passwordExpired`, passing `?forced=true` in the query string. The `ChangePasswordPage` then shows an info banner and signs the user out if they cancel.

## Customizing the login flow

The `Login` component reads its credentials form, then calls `useUserManagement().signIn(username, password)` directly. There is no `composable` override prop. To insert app-specific logic before or after the framework call, write your own composable around `useUserManagement` and use it in a custom wrapper page or in any callback that needs `signIn` and `signOut`.

```ts title="src/composables/useLogin.ts"
import { useUserManagement } from "@vc-shell/framework";

export function useLogin() {
  const { signIn, signOut, isAuthenticated, user } = useUserManagement();

  async function signInWithAudit(username: string, password: string) {
    const result = await signIn(username, password);
    if (result.succeeded) {
      // Pre or post sign-in hook: telemetry, locale prep, profile load, etc.
    }
    return result;
  }

  return { signIn: signInWithAudit, signOut, isAuthenticated, user };
}
```

If you need a deeper customization, for example, an extra confirmation step or a custom banner, register an `auth:after-form` extension point. The shared `Login` component renders that slot below the credentials form without you forking the page.

## Branding props

All four pages accept the same two branding props:

- `logo`. URL or imported asset for the centered logo above the form.
- `background`. URL or imported asset for the full-page background image.

`Login` adds `title` and `subtitle` for the form heading and supports an `ssoOnly` boolean that hides credentials when only external providers should be visible. `ChangePasswordPage` adds `forced` for the expired-password variant. `Invite` and `ResetPassword` carry `userId`, `userName`, and `token`, all required, all read from the URL query string.

## Common mistakes

!!! warning "Wrong asset paths"
    Vite serves anything in **/public/** from the root. Imports like `import logo from "/assets/logo-white.svg"` work only when the file lives at **public/assets/logo-white.svg**. Move the file there first; otherwise the build resolves an empty string and the layout shows a broken image.

!!! warning "Missing `userId` and `token` query parameters"
    The `Invite` and `ResetPassword` pages fail without the URL parameters that the Platform's email links carry. Both validate the token on mount and disable the form when validation fails. If you replace the email template, keep the `userId`, `userName`, and `token` query parameter names exactly.

!!! warning "Replacing the OAuth flow"
    The shared pages call `useUserManagement` under the hood, which speaks to the Platform's `/connect/token` endpoint and stores the result in `localStorage` under `vc_auth_data`. If you write a custom wrapper, return an object that exposes `signIn` and `signOut` and let the framework handle the storage. Replacing the storage manually breaks the request interceptor that attaches the bearer token to every API call.
