# UI

Recipes for styling a VC-Shell app: tweaking the color palette through CSS custom properties, extending the framework's Tailwind preset, composing on top of Vc components instead of forking them, and using the live Storybook to explore the kit.

## Prerequisites

Before customizing the UI, make sure you have:

- A VC-Shell app scaffolded and running. See [Generate an app from a prompt](../../getting-started/generate-app-from-prompt.md) or [Manual CLI start](../../getting-started/manual-cli-start.md).
- Basic familiarity with Tailwind CSS utility classes and CSS custom properties.
- An editor that resolves SCSS imports for **src/styles/custom.scss**.

## Recipe: theming with CSS custom properties

The framework ships two themes out of the box, `light` and `dark`, defined in **framework/assets/styles/theme/colors.scss**. Each theme is a flat list of CSS custom properties on `:root[data-theme="..."]`, with eleven shades per palette (50 through 950) for `primary`, `secondary`, `accent`, `neutrals`, plus state palettes (`warning`, `danger`, `success`, `info`) and surface, shadow, and overlay tokens. Tailwind's preset maps each palette shade to a `var(--<palette>-<shade>)` reference, so changing the variable propagates to every utility class and every Vc component.

To override the palette for your app, define your own theme block in **src/styles/custom.scss**:

```scss title="src/styles/custom.scss"
:root[data-theme="acme"] {
  // Primary
  --primary-50: #eef2ff;
  --primary-100: #e0e7ff;
  --primary-200: #c7d2fe;
  --primary-300: #a5b4fc;
  --primary-400: #818cf8;
  --primary-500: #6366f1; /* default */
  --primary-600: #4f46e5;
  --primary-700: #4338ca;
  --primary-800: #3730a3;
  --primary-900: #312e81;
  --primary-950: #1e1b4b;
}
```

Register the theme key with `useTheme` so the framework can switch to it at runtime:

```ts title="src/App.vue"
import { useTheme } from "@vc-shell/framework";

const { register, setTheme } = useTheme();
register({ key: "acme", localizationKey: "ACME.THEMES.ACME" });
setTheme("acme");
```

The active theme is written to `<html data-theme="acme">` and persisted to localStorage. To add a dark counterpart, define a second `:root[data-theme="acme-dark"]` block with darker values and register both keys.

- [useTheme reference.](../../composables/ui-state/useTheme.md)

## Recipe: extending Tailwind

Every app generated by `create-vc-app` re-exports the framework's Tailwind preset and the `tw-` prefix:

```ts title="tailwind.config.ts"
import defaultConfig, { content } from "@vc-shell/framework/tailwind.config";

export default {
  prefix: "tw-",
  content: [...content, "./src/**/*.{vue,js,ts,jsx,tsx}"],
  theme: defaultConfig.theme,
};
```

The `tw-` prefix exists so Tailwind utilities never collide with Vc component class names. Write `tw-flex tw-gap-4` in your templates, not `flex gap-4`. To add app-specific utilities, replace `theme: defaultConfig.theme` with a merged config that uses `extend`:

```ts title="tailwind.config.ts"
import defaultConfig, { content } from "@vc-shell/framework/tailwind.config";

export default {
  prefix: "tw-",
  content: [...content, "./src/**/*.{vue,js,ts,jsx,tsx}"],
  theme: {
    ...defaultConfig.theme,
    extend: {
      ...defaultConfig.theme.extend,
      spacing: {
        sidebar: "280px",
      },
      fontFamily: {
        brand: ["Inter", "sans-serif"],
      },
    },
  },
};
```

Use raw Tailwind utilities (`tw-p-4`, `tw-text-primary-500`, `tw-bg-surface-color`) for spacing, layout, and one-off color tweaks. Reach for a Vc component (**VcButton**, **VcCard**, **VcInput**) whenever the kit covers the affordance. Mixing the two is the intended pattern.

## Recipe: compose, don't fork

When a Vc component is almost right but you want different defaults across the app, wrap it in your own component rather than copying its source. The wrapper sets defaults, the underlying Vc component keeps its behavior and accessibility:

```vue title="src/components/AcmeCard.vue"
<template>
  <VcCard variant="outlined" class="tw-bg-additional-50 tw-shadow-md" v-bind="$attrs">
    <template v-for="(_, slot) in $slots" #[slot]="scope">
      <slot :name="slot" v-bind="scope" />
    </template>
  </VcCard>
</template>

<script setup lang="ts">
import { VcCard } from "@vc-shell/framework";
</script>
```

The wrapper inherits every prop, slot, and event from **VcCard** through `v-bind="$attrs"` and the slot loop, so callers can still pass anything the underlying component accepts. Forking the source would mean re-implementing keyboard handling, ARIA attributes, and shared variants, and you would lose every fix that ships in subsequent framework releases. Wrap, and you keep the upgrades for free.

- [VcCard reference.](../../components/layout/vc-card.md)

## Recipe: Storybook for visual exploration

The kit's Storybook lives at [vc-shell-storybook.govirto.com](https://vc-shell-storybook.govirto.com/). Each atom, molecule, and organism has a story with controls for every prop, side-by-side variants, and an MDX docs tab that mirrors the component's reference page in this guide. Use it as a sandbox: pick a component from the sidebar, flip variants in the **Controls** panel, copy the resulting markup straight into your blade.

To embed a specific story inline in your own documentation, use the `vc-storybook-embed` wrapper:

```html
<div class="vc-storybook-embed" style="--height: 400px">
  <iframe
    src="https://vc-shell-storybook.govirto.com/iframe.html?id=misc-vcbutton--default&viewMode=story"
    loading="lazy"
    title="VcButton default"
  ></iframe>
  <a href="https://vc-shell-storybook.govirto.com/?path=/story/misc-vcbutton--default" target="_blank" rel="noopener">Open in Storybook ↗</a>
</div>
```

The story ID follows the pattern `<group>-<component>--<variant>`, visible in the URL when you open any story. The `--height` CSS custom property controls iframe height.

## Recipe: server-driven branding with useSettings

`useSettings()` exposes a single source of UI customization that the framework loads from the Platform on startup through `SettingClient.getUICustomizationSetting()`: app title, logo, contrast logo, and optional avatar and role. Override the values at runtime through `applySettings(...)` when a module ships its own branding or you want a multi-tenant skin.

```vue title="src/pages/App.vue"
<script setup lang="ts">
import { useSettings, VcApp } from "@vc-shell/framework";

const { uiSettings, loading, applySettings } = useSettings();

// Override on top of the server-loaded settings.
function applyTenantSkin(tenantId: string) {
  applySettings({
    ...uiSettings.value,
    title: `Tenant ${tenantId}`,
    logo: `/tenants/${tenantId}/logo.svg`,
  });
}
</script>

<template>
  <VcApp
    :is-ready="!loading"
    :logo="uiSettings.logo"
    :title="uiSettings.title"
  />
</template>
```

`uiSettings` is reactive, so binding it directly to **VcApp** props means the chrome rerenders whenever `applySettings` is called or the platform fetch resolves. Each `applySettings` call replaces the entire object, so spread `uiSettings.value` first when you only want to change one field; otherwise the unset fields become undefined.

Calling `applySettings()` early, for example in **App.vue** setup, sets an internal flag that skips the Platform API fetch entirely. Use that path for fully custom apps that never read from the Platform.

## Variations

| Variation | Where |
| --- | --- |
| New brand color. | Override `--primary-*` variables in **src/styles/custom.scss** under a new `data-theme` block, register the key with `useTheme`. |
| Custom Tailwind utility. | Add to `theme.extend` in **tailwind.config.ts** after spreading `defaultConfig.theme`. |
| App-wide font. | Define `--font-family` in your theme block and add a `fontFamily` entry to `theme.extend` so Tailwind exposes a matching utility. |
| Dark mode toggle. | Register the built-in `dark` theme via `useTheme().register({ key: "dark" })` and bind a button to `setTheme("dark")` or `next()`. |
| Per-component override. | Wrap the Vc component as in **Recipe: compose, don't fork**; do not edit framework source. |
